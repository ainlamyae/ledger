# Ledger

A private, serverless personal life dashboard — health, finances, time tracking, travel, applications, and contacts in one place.

- Reads and writes **directly to a Google Sheet you own**. No backend, no database, no third-party data store.
- Public on GitHub Pages, usable by anyone with a Google account.
- Each user clones their own copy of the template; the app only ever touches that copy.
- Scoped via Google Drive's per-file `drive.file` permission — data is visible only to the account owning that sheet.

## Overview

- Single-page app; authenticates with the user's own Google account.
- Reads/writes a private "Ledger" spreadsheet via Sheets API v4.
- All aggregation, charting, filtering, sorting and CRUD runs client-side in vanilla JS.
- **All styling lives in `assets/style/styles.css`** — no inline `style` in any page or script. Chart colours are `--chart-*` tokens there too (read by `chartColor` / `seriesColor` in `charts-base.js` when a chart is drawn), and scripts pass only computed numbers to CSS as custom properties (`--meter-pct`, `--col-width`, `--keyboard-height`, `--gradient-color`…), so changing that one file restyles the whole app. Text uses six colours only: text, muted gray, white, red, green and blue (links); charts keep their own palette. Rows use two tints only: **green** for today's row or anything already logged today, and **indigo** for a Work Time day off (weekend and holiday alike); no row is faded. Every table line — the line under a row, the solid line above a Total, the dashed one above a Desire or Ideal/day — is one colour, **navy** (`--color-nav`); `table-compact` tables have no row lines at all. Backgrounds: the page is **off-white** (`--color-bg`) and everything on it — cards, tiles, inputs, buttons, menus, the GYM figures — is **white** (`--color-surface`). Text comes in seven sizes only: **.7rem** (badges, formulas, footer strip, the plan's small cells), **.8rem** (table cells, word buttons, labels, hints, menus), **.9rem** (breadcrumb, sidebar, cards, tiles, chart text), **1.1rem** (headings, form titles, emoji buttons) — plus **15px** for the text in every input, select and textarea, the same at every screen width, **1.25rem** (header title) and **1.4rem** (phone bottom-bar emoji, landing title, flags). Spacing — every margin, padding and gap — uses six steps only, defined once as `--space-xs` … `--space-xxl` at the top of `styles.css`: **.2rem**, **.5rem**, **.75rem**, **1rem**, **1.5rem** and **2rem**, each visibly different from the next; only the sidebar's own layout sizes sit outside them. Each look is written once: every field (form, filter, Export, Insight question, clock box, Tune) starts from one base rule, and repeated rules — cards, Total and target rows, small notes, dropdowns, field rows — are single rules shared by several selectors. Two shadows (`--shadow-card` for cards and tiles, `--shadow-dropdown` for anything floating: menus, toast, phone bars, hover), two line heights (1.2 for text and controls, 1.5 for paragraphs), one bold (600), one faded/disabled opacity (.5), two animation speeds (.2s for hover and colour, .3s for opening and closing), and two line thicknesses (1px borders, 2px emphasis lines). Buttons come in three heights only, the same on laptop and phone: **24px** (row buttons in tables), **30px** (every other button, the same as a field) and **42px** (the phone's action bar and the tiles); emoji buttons are square. Alignment is enforced by two `!important` rules: every field's text is **left**-aligned (dates included, which iOS would centre) and every button's text is **centred** (word, emoji and row buttons, tiles, the phone's tab and action bars), except the account menu, which is a left-aligned list, on laptop and phone alike.
- No build step, no server component to deploy or maintain. Run it locally with `python scripts/serve.py 8000` — `python -m http.server` plus GitHub Pages' `404.html` fallback, which the row addresses below need.
- **Nothing is cached.** There's no service worker and no stored copy of sheet data: every load and **Refresh** reads the sheets, so a change to the code or the sheet shows on the next load. The account menu's **Clear cache** (under Refresh data) is for when the browser itself still runs an old copy of the app: it clears Cache Storage and any service worker, re-downloads every script and stylesheet with `cache: 'reload'`, and reloads; sign-in and preferences are kept. `sw.js` remains only as a stub that removes the old offline cache from browsers that still have it. **Reads are light on Google's quota** (60 read requests per minute, counted per request, not per range): the spreadsheet's tab list is fetched once per load and shared, reads made together go out as one `batchGet`, and each page reads only what it shows — a Health page never reads Finance's tabs, and the home page reads only its glance cards' data plus Transactions and Work Time for its tiles' badges (5 requests). Each load logs its request count in the console (`[sheets] health load: N requests`). If the limit is still hit, requests wait and retry (about a minute in total) before showing "Quota exceeded". See [Caching Strategy](docs/caching.md).
- The home page is a fast overview: each section's glance cards (Health status/macros/activity/sleep and Progress, Finance net worth and monthly cash flow, with a Cumulative Net Worth card under them — just the line, no axes or grid — — every card's text — the Time/Date/Azan/Weather widgets included — at one size, `--card-text-size` (titles at their own one size), regular weight, with one padding) followed by that section's page tiles, with no section titles in between (the sidebar or the bottom tab bar already names them). It reads only what those cards need; a tile opens the page, which loads its block. The account menu's **Hide bulbs** (under Hide widgets) hides those glance cards on the home page only, kept across loads by a `SHOW_BULBS` Setting like `SHOW_WIDGETS`.
- **Hub and pages:** `/health/`, `/finance/` and `/other/` are hubs — the section's glance cards, then a name-only tile per block (Health's: Indicator, Physique, Nutrition, Activity, Insight, Tune, Settings, then **GYM** and **Today**, gray like Physique's own Today button) — and each block is its own page (`/health/physique/`) under a breadcrumb that starts at **Ledger** (the home page) — `Ledger / Health / Physique` — switched in place without reloading — and so is each form (Log, Add, Today, Edit, GYM: `Ledger / Health / Physique / Log`), which takes the page's place instead of covering it. Action buttons are emoji, always white like ❌ (never coloured; colours mark word buttons only) as 30px squares (24px for row buttons in tables, 42px in the phone's bottom bar; emoji 1.1rem, 1.4rem on that bar): **Save** 💾, **Add** ➕, **Log** 📝, **Update** 🔄, **Scan** 📷, **Calculate** 🧮, **Complete** 🧲 (pull from USDA), **Norm** 📏, **GYM** 💪, **Send to AI** 🤖, **Reset** ♻️, Physique's **Today** 📍, the selection bars' 🔗 ✏️ 🗑️ 📱 📧 and the Physique form's **Micronutrients** 🧬 — the word on hover, for screen readers and in the breadcrumb (`…/ Add`); busy, the emoji followed by …. **Keyboard shortcuts** (`?`) work from any page: `/` filters transactions by payee, `n` logs a transaction, `Esc` closes a form or menu. **Saving never closes a form**: 💾 shows "Saved" and keeps the form open — an Add becomes the new row's Edit, so saving again updates it rather than adding it twice; ❌ closes. Physique's page filters by its search box alone (no From/To dates). **Export Transactions** and **Export Physique** (every row, as CSV) live in Other › Settings. **Badges** flag a block from its tile — on its hub and the home page alike — and its breadcrumb in a few characters: `A<T $13` (Account: accounts below the transactions), `28d` (Car Service), `Log` (Work Time, Physique: today not logged; tapping opens today). Chrome notifications for Work Time and Car Service are switched on from the account menu's **Enable notifications**. Pages have no white card of their own — only small cards like Status, Progress and the tiles are white. The breadcrumb is the only heading, on every page — the home page's reads **Ledger** alone: a block page doesn't repeat the block's name under it, and a form page has no title of its own. On a phone the page's own actions are its bottom bar in place of the tab bar — both bars a navy pill floating just off the screen's edges, ❌ a round button, no blue line marking the current tab — the same height as the tab bar on every page (`--bottom-bar-height`), its buttons all one size and differing only in colour — and every page and form ends that bar with ❌ (on a laptop, ❌ sits at the top right of the page, after the page's own buttons). Reloading any page's address opens straight onto that page or form: the page reads its address as soon as the app's own scripts have run, before sign-in and the rest of start-up, and stays hidden until then, so it never flashes the whole section first. Wide screens replace the top bar with a sidebar of every section and page, **Ledger** (the home page) at its top and the account avatar and its menu in its bottom-left corner; phones use the bottom tab bar and the tiles, with no top bar: the account avatar and its menu sit at the bottom left. Signed out, a round 🔑 sign-in button sits in the avatar's place, the same shape and size. The Finance pages are **Indicator** and **Insight** (`/finance/indicator/`, `/finance/insight/`); Finance's Insight works like Health's — a **Snapshot** tile on `/finance/insight/`, opening `/finance/insight/snapshot/` with the question box first, then the data, Send to AI and the answer. See [Hub and pages](docs/features.md#hub-and-pages).
- **Loading and the actions bar:** reloading any address paints its final layout from the first frame — no blocks flash open while scripts load — and a form's address opens straight onto that form page (its breadcrumb shows … until the row's real name loads, never the lowercase address). Every page keeps its actions in one place, in one order, with ❌ last: at the top on a laptop (a block's own actions such as Tune's ♻️ 🔄 💾 join its header; a form's row sits under its title), and in the bottom bar on a phone. On a phone that bar starts with a **Ledger** tab for the home page, sits a little above the bottom edge, its account picture is the same circle as ❌ and as far from the first button as the buttons are from each other, and long labels wrap onto two lines inside their button (`Export` over `Transactions`). A logged row on Activity is marked like one on Nutrition — green, no tick, no hover note. On a phone the copyright line sits in a slim strip under the navy bottom bar, between it and the screen's edge, always in view, and a short page fits without scrolling; date and time fields align left like every other field. The Progress card ends at its last bar unless it has a note to show (reached, no change, wrong direction, levelling off). The day form leads with 📷 Scan, then 🧬, 🧮, 💾, and its **Workout** box suggests the Activity sheet's exercise names line by line, like Consumption's ingredient names, keeping the amount typed (`36x row` → `36x Seated Row machine`); the ingredient form with 📷 Scan before Complete, its value list's names and units at the page's text size and only as wide as their text.
- **Stored, not recalculated:** the glycogen/water swing (`± 1.9 kg`) is the `GLYCOGEN_SWING_KG` setting, saved once from your latest body-mass reading and updated by Tune's Save; each day's body-mass figures live in its BMR cell. Each load logs where its time goes in the console (`[load] health: page + sign-in … ms, data … ms`, plus `[sheets] … requests`), and a background Physique write says so (`… writes and re-reads Physique`), which should only happen while something is missing.
- **Wording:** the app says **body mass**, never "weight", for the body; an exercise's dumbbell or machine load is labelled **Load** (the Activity sheet's Weight column, read by position, can keep its header).
- **Every block and form has its own address**, like a breadcrumb: `/health/tune/`, `/health/physique/log/`, `/finance/account/transfer/`. Opening a block or form updates the address; loading one reopens it; Back closes a form. Insight's modes have addresses too (`/health/insight/plan/`, `…/pattern/`, …), and so does each row's Edit: `/health/nutrition/chicken-breast/`, `/health/physique/2026-10-03/` (Physique's **Today** uses today's date address too, logged or not) (a Pattern is `/health/physique/pattern-1/`), `/health/activity/swim/`, `/other/settings/body_mass_target_kg/` (a setting's key in lowercase), `/other/contact/jane-doe/`, `/other/work-time/2026-10-05/`, `/finance/transaction/2026-10-05-grocer/` (Contact, Account, Breakdown, Transaction, Travel and Application rows by their label; a repeated label gets `-2`, `-3`… in sheet order), a row's 📋 one level down (`/finance/transaction/2026-10-05-grocer/duplicate/`, likewise Physique and Activity), Transaction's Bulk Edit (`/finance/transaction/bulk-edit/`), and a day's 🧬 view, `/health/physique/2026-10-03/micronutrients/` (a Pattern's 🧬 view totals its own Breakdown, like a day's). Every form opened from elsewhere is a page too: Activity's and Nutrition's Log, and the Health reminder's, open today's day (`/health/physique/2026-10-05/`), Work Time's reminder today's day there, and a breakdown line's ✏️ in the Physique form the ingredient's page over the day. Row addresses are served by `404.html`, since they have no folder of their own. `sitemap.xml` lists every block, button and view address (`python scripts/build_sitemap.py`), but no row addresses, which would publish the sheet's own names and dates. One block is open at a time. See [Addresses](docs/features.md#layout-and-interaction).
- **Tune** (formerly the Health Formula Playground modal) is a block of its own in the Health section, after Insight, and does the BMR calibration itself (the separate Calibrate form is gone): `n_p` × `L_p` (default 3 × 10 days, ending yesterday) give `BMR_cal` live (Save stores only `n_p` and `L_p`; the calibration itself is each day's stored `BMR_cal` in Physique), and its **Update** button recomputes every day's stored `BMR_cal` with a new window. Both of Tune's BMR choices offer the same four, always in step — `BMR_mif`, `BMR_kat`, `BMR_cal`, `BMR_adp` — and the adaptation rows (λ, λt_max, BMR_adp, m∞_adp) sit right under `BMR_cal`. Tune's variables open with the profile in this order — `σ` (sex), `h` (height), `a` (age), then `m`, `L_p`, `m̄` — the same order every Insight mode's profile block (Sex, Height, Age, Current body mass, BMI) and the Plan prompt's inputs use. `L_p` sits under `m`, directly above `m̄`, because it is also `m̄`'s window: `m̄` is the rolling average of body mass over `L_p` days (`m̄ = (1/L_p) × Σ m(t−i), i = 0…L_p−1`), everywhere in the app, and Tune re-smooths it live as `L_p` is typed. Tune's names, units and computed values are in the normal text colour. Tune's model sits in two collapsed dropdowns: **Equations** (the full equation list, above the variables) and **Calculations** (the live substituted arithmetic under the last row, including BMR_cal's Periods table).
- **Physique columns are matched by header name**, so the sheet's column order can change freely. Each day's **Sleep**, **Deprivation**, **BMR** (JSON: the four BMR figures plus the body-mass figures `m`, `BMI`, `m_avg`, `m_d`, shown in the day form above the BMR line and read by Status and the Body Mass chart) (JSON: `BMR_mif`, `BMR_kat`, `BMR_cal`, `BMR_adp`) are computed once and **stored in the sheet**, and the Status card, the charts and the table read them instead of recalculating on every load. Missing ones are filled in on load; a changed profile or BMR setting rewrites them all in one request. Re-saving a day keeps its stored BMR unless that day's Body Mass changed. **Breakdown amounts are in grams**: a food counted by unit is stored as its weight from its Nutrition row (`1 scoop (31g)` → `31g`), and older `×N` amounts were rewritten to grams once on load; `×N` remains only for a food whose Nutrition row names no weight. The Edit Physique breakdown table's last column (✅ / estimator + 💾) has no header label, to keep it compact, and the Workout table stays hidden until there's a workout to price, like Consumption's. See [Data Model → Physique](docs/data-model.md#physique).
- **One name for everything, app-wide**: the four BMR figures are always called `BMR_mif`, `BMR_kat`, `BMR_cal` and `BMR_adp` — in the Physique form (one line under Date and Body Mass, names grouped then values: `BMR_mif/kat/cal/adp: 1692/1638/1663/1441 kcal`, the unit once at the end), the Status card, Tune, the Caloric Intake chart (which draws all four per day) and every hover. Physique's form labels match the sheet's headers (**Bed**, **Wake**, and **Sleep** · **Deprivation** under them). **Units are standard symbols** — `g`, `mg`, `µg`, `IU`, `kcal` — never USDA's upper-case `G`/`MG`/`UG`, in forms, tables, Insight and the sheet itself. Hover lines read `label (definition): number unit`, e.g. `TEI (Total Energy Intake): 829 kcal`, with a sign only on negatives in Calorie Balance. In every chart's hover, a **7-Day Average** is an amount with no `/day` (`1309 kcal`, `134 g`; sleep's 7-Day Average Bed/Wake are clock times), while a **7-Day Trend** — a slope — always carries it (`-71 g/day`). **Every date reads `YYYY-MM-DD`** — tables, the Progress card's arrival date, chart axes and hovers (`2026-10-04`, or `2026-10` on a month axis) — and the home page's Date card reads year, month, day.
- **Status card** (Health), in four groups split by a line: `m` — today's reading with the L_p-day rolling average `m̄` in brackets, against the target and the glycogen/water swing (`80 (80.6) / 70 ± 1.9 kg`) — BMI, and the measured **Δm** — the Body Mass chart's Changed Mass at the latest body-mass reading against the desired rate from Tune's weekly Δm (`-108 / -101 g/day`); then `BMR_mif`, `BMR_kat`, `BMR_cal`, `BMR_adp`; then TEI, TEF, AEE, SD; then D and **Δm′**, the change *calculated* from D (primed so it isn't mistaken for the measured Δm). Intake Macros, Physical Activity and Sleep (Window, then Duration) stack beside it at their own height, top and bottom aligned with Status and the spare space between them. Under both columns, a full-width **Progress** card holds the kg and days bars (marked every 10%, target as `→ 70 ± 1.9 kg`); it is on the page from the first paint with `—`, like the other cards, and fills in when the data arrives. The Body Mass chart's **7-Day Trend** hover reads in g/day, like Δm and Calorie Trend Slope.
- **Nutrition** — the **Add/Edit Ingredient** form stacks Classification, Name, Protein % and **Amount** (never touched by Complete), then a lock table, one row per value: **tick, name, box, unit**. Names and units match the form's labels; the name and unit columns are as wide as their longest text (the name wraps only on a screen too narrow for it), the box one fixed width. TEF comes first, then the Nutrition Facts lines in label order — Calories, Fat, Saturated, Trans, Polyunsaturated, Omega-6, Omega-3, Monounsaturated, Carbohydrates, Dietary Fiber, Soluble and Insoluble Fibre, Sugars, Sugar Alcohols, Starch, Protein, Cholesterol, Sodium, Potassium, Calcium, Iron (each shown when the food has it, under its Canadian Nutrition Facts name; `NUTRITION_FACTS_ORDER`, also used by Micronutrient Insight and Physique's 🧬 view) — then, under a divider, every other micronutrient alphabetically, with zeros at the end below a line of their own. A ticked row is locked: **Complete** (formerly Pull Micronutrients) fills every other row from USDA, scaled to Amount, and refreshes an unticked TEF from the new macros. **Scan** fills them instead from a photo of the product's Nutrition Facts label (bilingual Canadian labels included) through your Groq key: a line printed only as a % Daily Value is converted with Health Canada's Daily Values, a blank Name and Amount take the label's, and a typed gram Amount rescales the label's figures to it. **Norm** 📏 (formerly Normalize) capitalizes Name and rescales everything to a 100g Amount. **Log** always reads Log (never Log More), here and on Activity. The **Micronutrients** column stores the same thing as JSON: the six top values first, then the micronutrients, each `{amount, unit, locked}`. The old **Verified** column is gone from the table and the sheet; its ✓s became locked Amount–Carbohydrates. The table's **Micro** column shows how many micronutrients are non-zero. Columns are matched by header name, like Physique. See [Data Model → Nutrition](docs/data-model.md#nutrition).
- **GYM** (`/health/activity/gym/`, Activity's 💪, and a tile on the home page and the Health hub) — one tile per strength Group (activities with Sets x Reps; NEAT and Cardio stay out), each its own page (`/health/activity/gym/leg-day/`, breadcrumb `Ledger / Health / Activity / GYM / Leg Day`). A group's page shows a card per activity: its figure (an empty box of the same size when it has none), name, muscle group, and the sets/rest line (`3 x 10 · 90 sec rest`) in the text colour. Tap a card (or its corner tick) to pick it and 📝 saves the picks straight into today's Physique row — priced like the form's Calculate, with an undo toast, no jump to Physique; cards already logged today are tinted green and can't be picked twice. ✏️ in the figure's other corner opens that activity's Edit page, and its ❌ comes back. ❌ on a group's page goes back to GYM's tiles.
- **Car Service** (Other section, `/other/car-service/`) — your car's past services from Transportation transactions with an `@<km>km` odometer, a linear odometer forecast, and the next service of each kind: Toyota's 2023 Corolla km schedule (km only, no month limits), your own oil-change average, Ontario winter-tire timing (predicted on TD's 1 Dec deadline, off after 31 Mar), and a new tire set every 6 years. The tire Basis states only TD's hard dates: winter **at +7 °C or below, by 1 Dec — TD** (its Ontario discount needs winter tires on December–March) and all-season **after 31 Mar, above +7 °C — TD**. Each tire changeover also counts as Toyota's rotation & inspection, and rust protection is predicted with the changeover to winter. Two tables, **Predicted** (Date, Odometer, Service, Basis) above **Done** (Date, Odometer, Service), one line per cell, Basis included; every Basis credits one source: **— Toyota**, **— TD** or **— your own history**. A service due within 30 days (or overdue) puts a badge on its tile and breadcrumb — `28d`, or `-3d` once overdue — and, with notifications allowed, a once-a-day Chrome reminder. See [Features → Other](docs/features.md#other).
- **Settings** (Other section, `/other/settings/`) — the Setting tab's Key / Value / Notes rows. It's the one Settings page: every key, health ones included. Keys are listed alphabetically. Values that live elsewhere are never Settings: the walking MET is the Activity sheet's **Walk** row (Tune's MET box is a preview-only what-if), and BMR_cal is read from the latest Physique day's stored BMR cell — the old `ACTIVITY_MET`, `ACTIVITY_MET_DEFAULT`, `BMR_CALIBRATED_KCAL` and `BMR_CALIBRATED_OFFSET_KCAL` rows are deleted from the Setting tab on load. Each row's Edit has its own address, the key in lowercase (`/other/settings/body_mass_target_kg/`), and **Value** is a multi-line box for long values such as the targets JSON, trimmed on save.
- Optional AI reads (via your own Groq key) in the Health section's Insight block. `/health/insight/` shows only its seven modes, as tiles like the hubs' (no card behind them); each mode is its own page (`/health/insight/plan/`, breadcrumb `Ledger / Health / Insight / Plan`) laid out top to bottom as From/To, the question box, the prompt template, the mode's data, Send to AI, then the AI's answer. Back or ❌ returns to the tiles. The modes — Plan (first), Wellness, Food (whose Fiber/Fat/Carbohydrate/TEF fall back to the logged Breakdown's own figures when a food has no Nutrition row or lacks that value), Micronutrient (`/health/insight/micronutrient/`; which skips any nutrient at 0 with no daily target, and lists the Nutrition Facts lines first under their Canadian names, then nutrients with a daily target, then the rest, with a rule between each block — Physique's 🧬 view too; its targets come from the `MICRONUTRIENT_DAILY_TARGETS_JSON` setting, which once it exists is the whole list, so a nutrient deleted from it has no target), Activity, Protein, and **Pattern** (`/health/insight/pattern/`; Protein Sources is now **Protein**, `/health/insight/protein/`). Each mode has a **Prompt template** dropdown (Tune's Equations style) showing exactly what Send to AI sends: the full system prompt and the user message, with the data already on screen shown as `[data shown above]`. Pattern's Periods table is sized to its content in the compact table style — one line per cell, scrolling sideways when wide. **Pattern** sends period averages (mass change, the four stored BMR figures, intake, macros, activity by type, BMR offset) over a **period length** that starts at Tune's `L_p` (default 10 days) and can be changed right there, and asks what drives more fat loss and a higher BMR.
