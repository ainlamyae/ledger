# Health — Nutrition

[← Features](README.md) · [README](../../README.md)

## At a glance

- **Add/Edit Ingredient:** Classification, Name, Protein %, **Amount**, then a lock table: tick, name, box, unit.
- Row order: TEF, then Nutrition Facts lines in Canadian label order (`NUTRITION_FACTS_ORDER`), then other micronutrients alphabetically, zeros last.
- A ticked row is locked:
  - **Complete** 🧲 fills unlocked rows from USDA, scaled to Amount.
  - **Scan** 📷 reads a Nutrition Facts photo via Groq (bilingual labels; %DV-only lines converted with Health Canada Daily Values).
  - **Norm** 📏 capitalizes Name and rescales to 100g.
- The **Micronutrients** column stores JSON: six top values, then micronutrients, each `{amount, unit, locked}`. The table's **Micro** column counts non-zero ones.
- The old **Verified** column is gone; its ✓s became locked rows.
- See [Data Model → Nutrition](../data-model.md#nutrition).

## Health — Nutrition

- The panel heading reads **Nutrition**; `Nutrition` stays the name of the sheet tab behind it, and of the Source label a Calculate row gets when it matched that tab.
- **Log**, beside catalogue **Add** — same two-button shape as Activity Plan. Tick rows with the same per-row checkbox the bulk actions below use, click it, and each ticked ingredient is appended to today's Physique **Consumption** as a bare `unit name` line, so all that's left is clicking at the front of the line and typing the amount, then Calculate, then Save, rather than retyping the name from scratch. The unit is `g` by default, but `x` for a row whose own Amount is written the discrete/per-each way Edit Ingredient shows it (e.g. egg's `1x (58g)`) — `nutritionLogUnit` reads that off the same unit extraction a typed Consumption line itself goes through (`extractIngredientQuantity`), so a per-each ingredient asks for a count in front rather than a gram figure it was never logged in. Opens the Physique form on today's row (or a fresh one) with any Consumption already there kept and the new lines appended after it; doesn't run Calculate itself, since the line is deliberately incomplete until an amount is typed. Always reads **Log**; its hover says whether today's Consumption already has something in it — same rule, same reason, as Activity's own toggle.
- Searchable, sortable ingredient table backed by its own sheet tab.
- **Classification** is the first column — a free-text grouping (Dairy, Poultry, Grain).
  - The Add/Edit form offers a datalist of classifications already in use, so the column doesn't fragment.
  - Search matches classification **and** name, so typing `dairy` pulls up the whole group.
  - Left blank by Calculate's auto-bank — the app has no basis for guessing one.
- **Add/Edit Ingredient form** — Classification, Name and Protein % on top, then every value as one row in Tune's layout: **tick, name, box, unit**. The fixed rows are Amount, Calories, Protein, Dietary Fiber, Fat, Carbohydrates and TEF; below a divider, one row per micronutrient Complete has pulled (Ash, Iron, Vitamin C, …), every box typeable. **A ticked row is locked**: Complete never overwrites it. Amount is always kept (its tick is fixed on). A blank TEF uses the Atwater/TEF-share estimate.
- **Complete** (formerly 🧬 Pull Micronutrients) — the same button in the form and as the bulk table action: given a Name and an Amount with a real gram figure, it looks up USDA FoodData Central's top match and fills every **unticked** row — Calories, Protein, Fiber, Fat, Carbohydrates and the micronutrient rows — scaled to Amount. Ticked rows keep their values, unticked TEF is refilled with its estimate from the new Protein/Carbohydrates/Fat, and Amount is read, never written (no gram figure → "Amount has no gram figure to scale from").
- **Scan** (form only, `scanNutritionLabel`) — a photo of a product's Nutrition Facts label (bilingual Canadian labels included) goes to Groq's vision model (`groqReadNutritionLabel`), which maps each printed line onto the form's own rows (USDA panel names, so the totals and Insight read them like Complete's). Unticked rows take the label's figures; other micronutrients already in the form stay. A line printed only as a % Daily Value is converted with Health Canada's Daily Values. A blank Name and Amount take the label's; a typed gram Amount rescales the per-serving figures to it. Free-tier Groq allows 1000 output tokens a minute, so the call caps its output and turns the model's thinking off.
  - The Micronutrients JSON (column K) mirrors the form: Calories, Protein, Dietary Fiber, Fat, Carbohydrates and TEF first, then the micronutrients, each entry with its own `locked` tick. The old **Verified** column is gone (table and sheet): every ingredient that had its ✓ now has Amount–Carbohydrates locked instead (the label's own values, not TEF).
  - In the form, nothing is written until Save; the bulk action writes each selected row's unticked Calories, Protein, Fiber, Fat, Carbohydrates and TEF cells and its Micronutrients straight away, keeping ticked values.
- Merge Selected consolidates near-duplicates; matching is exact-text, never fuzzy.
- **Update**, in the Edit Ingredient form (hidden on Add — there's no old name to search Physique for yet), beside the ordinary **Save**. Save alone only ever touches this one row; **Update** saves it, then sweeps every Physique day for the ingredient's OLD name and rewrites whatever it finds: renames the Consumption line, and — for any line whose unit can be locally rescaled by weight or count — reprices its Breakdown entry's Calories/Protein and that day's totals too, using the just-saved Amount/Calories/Protein. Exists because ordinary Calculate reuses a day's saved Breakdown by exact noteLine text match, so it never re-checks an unchanged line against the Nutrition table once it's been priced — a renamed or re-priced ingredient otherwise leaves every past day quietly wrong until Update reaches back and fixes them. Local only, no AI. One undo toast covers every Physique row it touched; the ingredient save itself isn't part of that undo.
- **📊 Count Uses**, beside Search — tallies how many logged Consumption lines (across every Physique day's own Breakdown, matched by `findNutritionEntry` the same way Calculate itself matches) resolved to each row, filling in a **Uses** column so you can sort it — ascending by default, least-used first — to spot ingredients you've stopped logging and remove them. UI-only: the count is never written to the sheet, just held in memory and thrown away on the next click rather than kept in sync with edits in between. Shows `—` (not `0`) until the button's been clicked at least once this session, so "never logged" reads differently from "haven't checked yet". Pulls in Physique's own data itself if the Physique panel hasn't been visited yet this session (`refreshPhysique`, cached either way).
