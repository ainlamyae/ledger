# Health — Physique

[← Features](README.md) · [README](../../README.md)

## At a glance

- Columns are **matched by header name**, so sheet column order can change.
- **Stored, not recalculated:** Sleep, Deprivation and Derived (JSON: the four BMR figures plus `m`, `BMI`, `m_avg`, `m_d`) are computed once and saved. Status, charts and the table read them.
- Missing values fill in on load; a changed profile or BMR setting rewrites all in one request. Re-saving a day keeps its BMR unless Body Mass changed.
- **Breakdown amounts are in grams:** a unit-counted food is stored as its Nutrition weight (`31g (1 scoop)` → `31g`); `×N` remains only when no weight is known.
- Day form order: 📷 Scan, 🧬, 🧮, 💾. **Workout** suggests Activity names line by line, keeping the amount (`36x row` → `36x Seated Row machine`).
- **Confetti:** saving today's Body Mass closer to the target than the last earlier reading drops confetti (`confetti.js`, also fired by an income transaction save — see [Finance](finance.md); off under reduced motion).
- The breakdown table's last column has no header; the Workout table stays hidden until there's a workout to price.
- See [Data Model → Physique](../data-model.md#physique).

## Health — Physique

- One row per day. Filterable/sortable table (search, date range), paginated; add/edit/delete/duplicate.
- **28 dated days (4 weeks) per page, plus every Pattern row** — a template isn't a day, so patterns never count against that 28 and instead show in full on every page, always at the top (`getPhysiquePageEntries`). Patterns still float to the top of the sort itself regardless of column/direction, so page 1's patterns are the same set on every page.
- **Log a Physique** sits in the panel heading — every panel's primary action does now (`.panel-header`), which also keeps it reachable while the panel is collapsed; **Pattern** saves a dateless template that 📋 Duplicate turns into a real day. Ticking Pattern hides Date, Body Mass, Bed and Wake, and a pattern saves them blank.
- **Today**, beside Log, opens today's own entry in Edit — or a fresh Log form pre-filled with today's date if nothing's logged yet — at today's date address either way (`/health/physique/2026-10-05/`, the same one the row's Edit uses; the old `/health/physique/today/` lands there too) (`todaysPhysiqueDay()`, the same day lookup Log a Workout already extends rather than duplicating a row for).
- **Scan** sits in the Log form's own footer, beside Calculate. Click it, pick a photo of a meal, and the Groq vision model (`qwen/qwen3.6-27b`) identifies every visible food item and estimates realistic portion sizes — appending a plain ingredient list, in the same format the Consumption field expects, to whatever's already typed there, then running Calculate automatically. Living inside the form rather than the panel heading, it adds to a day already in progress instead of always starting a fresh one — the button used to open a blank form itself, which was fine when nothing existed yet to lose, but would silently wipe a bedtime, body mass or hand-typed food already sitting in the open form now that Scan lives beside them. On failure the form is left exactly as it was and the error shows inside it.
  - The hidden file input behind it deliberately carries no `capture` attribute — that would jump straight to the iOS Camera app instead of the native picker sheet, and the app switch can make Safari reload the page under memory pressure while the camera's open, dropping the `change` listener the whole flow depends on before it ever fires. Without it, iOS shows its full sheet — Photo Library *and* Take Photo — without leaving the page.
- **Calculate** in the form fills Breakdown / Calories In / Protein In from Consumption and Activity Duration / Calories Out from Workout — all four of which are hidden fields, read instead off the Total row of the table under each of the two text areas. Both text areas themselves are rewritten too: Consumption through the tidy-up below, Workout through its own counterpart — see the tidy-up bullets below for both.
- **A `Desire` row sits directly under each table's Total, dashed off from it rather than bold-bordered like Total, and a `Remain` row (Desire − Total) sits under that, on today's own form only** (`renderCalcBreakdown`/`renderPhysiqueActivityBreakdown`, gated on the form's own Date field matching today), so what the day actually did has both an in-table goal and the amount still left to reach it. Every other day is read after the fact, so "still left to reach today's goal" doesn't apply to it — neither row (nor its dashed divider line) renders there at all. Remain is unclamped — once the Total passes the Desire it reads as a negative surplus rather than a flat zero. The Consumption table's Desire reuses the exact figures the Wellness tiles/charts already compute — `getCalorieTarget`, `getProteinTargetBandG`/`getFiberTargetBandG` (band floor only, not the full range — a `109~133` reads too wide for this table's narrow columns), the FDA Daily Value reference for Fat/Carbohydrate (`nutrient-targets.js`, no personalized formula for either yet), and the TEF the calorie target itself would cost (`calTarget.kcal × (1 − tefDivisor())`, the Tune's own "energy spent digesting" figure — left blank, like the Playground, when TEF isn't being counted). The Workout table's Desire is `getActivityTargetMin`/`getActivityTargetKcal` at today's Body Mass — the same pinned-vs-flat `ACTIVITY_TARGET_MIN` rule the Physical Activity tile and chart use, so neither table's goal can drift from what "hitting it" means elsewhere in the app. Like Consumption's, the Workout table is hidden while Workout is empty, so a fresh Log doesn't open on a 0 Total; it appears once there's a workout to price.
- **Consumption and Workout are collapsed `<details>` dropdowns, open by default only on today's own form (Consumption on a Pattern's too)** (`physique-consumption-details`/`physique-workout-details`, set in `openPhysiqueForm`) — same disclosure style as Tune's Equations/Calculations. A **Pattern** opens with Consumption expanded too (Workout stays collapsed), since the food is what a pattern is for. Every other day opens collapsed, so an old day's edit doesn't open on two empty-looking boxes; expanding either is still one click away.
- **A third dropdown, `Derived`, sits under the Workout table** — a plain table (`Name`/`Amount`/`Desire`/`Unit`) of every figure Save's Derived column stores plus the energy-balance pieces that lead to it: `m̄`/`Δm`/`BMI` (one line-under-BMI divider), `BMR_mif`/`BMR_kat`/`BMR_cal`/`BMR_adp` (shown **negative**, an expenditure, like the Status card's own BMR rows; one line under `BMR_adp`), then `TEI`/`TEF`/`AEE`/`SD` (one line under `SD`), then `D` and `Δm′` — same label set, same figures, as the Status card's own energy tile (`setStatusEnergyTile`, `wellness-charts.js`), just off this form's own typed fields rather than a saved entry. **Desire** is each row's plan-level target where one exists — the Body Mass target and its BMI, the weekly fat-loss rate (as `Δm`'s kg/day and `Δm′`'s g/day), the calorie target and what follows from it (`TEF`/`AEE`/`D`), and a flat `0` for `SD` — blank for the four BMR rows, which have no target of their own, same as the Status card doesn't pair them with one either. Same open-only-today default as Consumption/Workout.
- **Consumption accepts a `(<lines>)/<n>` wrapper** for logging a shared portion — a recipe split `n` ways, a fraction of a batch actually eaten — without hand-dividing every line's amount first. Calculate strips the wrapper and divides each line's own quantity by `n` (`applyConsumptionDivisor`, reusing `extractIngredientQuantity`/`extractIngredientName`) before running its normal estimate, rewriting the field to plain, already-scaled lines. A line whose quantity can't be parsed is left as typed rather than guessed at.
- Form layout: Date + Body Mass share a row, Bed + Wake the next. The pairs use `minmax(0, 1fr)` columns and the date/time inputs drop their native appearance — a bare `1fr` floors a track at its content's min-content width, and iOS Safari otherwise sizes a picker to its own content and ignores a smaller `width: 100%`, either of which leaves the plain text box beside it looking narrower.
- **Sleep Duration**, printed under Bed + Wake, updates live as either field is typed (`updatePhysiqueSleepDuration`) — the same live-readout pattern Work Time's own duration line uses, off the wraparound-aware `sleepDurationHours` the Sleep chart and its own Physique-derived entries already share, so a bedtime past midnight and a wake time the next morning read as one span instead of a negative one.
- **Confetti for progress** (`celebrateBodyMassProgress`, `physique.js`; `confetti.js`) — saving today's day drops confetti, like iMessage's celebration, when its Body Mass is closer to `BODY_MASS_TARGET_KG` than the latest earlier reading.
  - Direction comes from the target, so it works for a cut or a bulk.
  - Fires after 💾 succeeds, and only when the Body Mass is new or changed, so re-saving the same day doesn't repeat it.
  - Skipped on past days, Patterns, a first-ever reading, and under `prefers-reduced-motion`.
  - About 160 pieces fall from the top for 3 s, then fade; colours are the `--chart-*` tokens. The canvas (`.confetti-canvas`) sits above everything with `pointer-events: none`, so typing carries on.
- **Saving onto a day already logged merges into it** rather than being refused: the first Save folds that row into the form, the second commits. Details under `Physique` below.
- **🧬 Micronutrients**, a fourth row action beside ✏️ Edit / 📋 Duplicate / 🗑️ Delete, opens a read-only view of that one day's real, USDA-sourced nutrient totals — the Insight Micronutrients mode's own `aggregateMicronutrientIntake` narrowed to a single-day range, so Total and Avg/day always collapse to one figure and the table drops to three columns: Nutrient, Amount, Ideal / day. Same alphabetical-by-known-ideal-then-alphabetical ordering, same severe/mild row coloring, as the Insight table above — the two can't drift since they share the same aggregation and severity functions.
- **Consumption suggests ingredient names as you type, scoped to whichever line the caret's on** — typing `1x a` after the quantity surfaces `apple` from the Nutrition catalogue (`allNutritionEntries`), prefix matches ranked before substring matches. A hand-rolled dropdown rather than a `<datalist>`: a `<datalist>` only ever suggests a whole `<input>`'s value, the way Transaction's own Payee/Description/Category fields do (`tx-*-options`, `transactions.js`), and can't attach to just one line of a multi-line `<textarea>`. Arrow keys + Enter/Tab, or a click, accept the active suggestion — replacing only the name portion of that line, leaving the quantity typed in front of it and every other line untouched. On a narrow viewport it tracks `window.visualViewport` and sits just above the caret's line (below it when there's more room), inside the visible area, so it covers neither that line nor the keyboard and iOS's ∧ ∨ Done bar.
- **Calculate also tidies Consumption** — merges duplicate lines (same name and unit), reorders what's left by calories and capitalizes names, local only — no Groq/USDA. The form has no separate Tidy button; the bulk bar's Tidy still runs it across selected days without recalculating.
- **Calculate does the same tidy-up to Workout, with no separate button of its own.** Two lines for the same exercise **and the same quantity type** (`combineWorkoutText`) sum into one — two `x` rep lines add their reps, but an `x` line and a `min` line for the same exercise stay separate, since summing a rep count into a minute figure wouldn't mean anything as one token. A line the parser doesn't recognize passes through untouched rather than vanishing. What's left is sorted highest-calorie-burn exercise first, same order Calculate gives Consumption, then written back into the Workout box and the activity table below it. Only on an explicit Calculate click — the on-open reprice (`refreshPhysiqueActivityBreakdown`, runs whenever the form opens so Duration/Calories Out are current) sorts the table the same way but leaves the typed Workout text alone, so opening a saved day never silently rewrites it. A merge shows as `🔗 N workout lines combined.` alongside Calculate's other messages.
- **The form footer carries two more buttons beside Calculate / Save**: **TEF** re-estimates the hidden TEF field from whatever's already in Breakdown, local only — no Groq/USDA — for after pulling 🧬 Micronutrients on an ingredient without re-running Calculate; **Micronutrients** opens the same 🧬 view as the row action, without leaving the open Edit form. Micronutrients needs the day already saved (it reads `aggregateMicronutrientIntake` off the sheet, not this form's own unsaved fields) and says so if you haven't saved yet.
- **Select rows, then Calculate / TEF / Combine & Sort in the bulk bar** to run the same actions across whole days at once. Calculate uses the same two estimators and incremental reuse as the form's own button — a line whose `noteLine` still matches that day's saved breakdown keeps its numbers, so re-running a stretch of days only pays for what changed. It also runs the same Workout combine + highest-burn-first sort the form's own Calculate does, rewriting each selected day's Workout column, not just its Duration/Calories Out. TEF re-estimates from each selected day's *already-saved* breakdown, same as the form's own TEF button, and never touches Groq/USDA either.
  - Each day's burn uses **its own** Body Mass where it has one, falling back to the most recent day that recorded one — so a historical row is priced with the body mass it was actually logged at.
  - Days with neither a Consumption nor a Workout are skipped and counted (Calculate); days with no 🧬-priced ingredient in their breakdown are skipped and counted (TEF) — per-day failures don't stop the rest either way.
  - Progress shows in the selection summary, and the whole run is one undo.
